# Artwork

Everything recorded here is **Jeremy Kenedy's own work**, first-party, under this repository's
MIT licence (`LICENSE.md`), with the same standing as the source code. None of it is a
vendored component and none of it gets a vendor row (the clean-room rule, as clarified). The
one third-party icon set, Heroicons, has its own record under `firmware/main/vendor/heroicons/`
and this file claims nothing about it.

## The drawn icons: `tools/ui/src/icons/`

Nine icons drawn in Illustrator on a 96-unit grid, from the PandaVent working files, landed
here as the committed source of truth after `tools/ui/normalize_icons.py` rewrote each export
for function, not provenance: the twenty-class stylesheet became the three or four
attributes each element actually uses, `#010000` became `currentColor` so the icon follows
the theme, and the export furniture (the XML declaration, `id="Layer_1"`,
`enable-background`, `xml:space`, `xmlns:xlink`, attribute-less groups) went. The viewBox,
every coordinate and every stroke width are exactly as drawn.

**Stroke weight.** The drawn set uses 4 for primary strokes and 2 for detail on the 96 grid,
which is 1.0 and 0.5 at 24 px against Heroicons' 1.5. Rendered side by side at 24 px on both
themes they read as one family, Heroicons a touch heavier, so nothing was changed. If the
two should sit closer, the cheaper move is Heroicons' symbol attribute in
`tools/ui/build/build.py` (1.5 to 1.25), not the artwork.

**Where each icon is used.** Heroicons for generic chrome; the drawn set for the print
stages, the printer and the bar.

Also: `printer-enclosed` for the Printer destination in both navigation bars, on the
dashboard's printer tile and on the printer page's bound-printer tile; `printer-open` is
filed for the day a printer without an enclosure needs it.

**The sprite.** The page build splices every icon, this set and Heroicons alike, into one
inline `<svg>` of `<symbol>`s so the page makes one request. That sprite is a build artifact
of two sets under two licences; its hash fingerprints the mixture and is evidence about
neither set (`docs/ARCHITECTURE.md`). This set's symbols carry their own attributes and the
sprite imposes none on them.

**The real count, for the record.** PandaVent's page sprite carries 50 symbols. 36 are
Heroicons 2.2.0 outline paths, several under other names; 3 more are Heroicons from other
versions (`video-camera` from 2.0.18; `circle-stack` and `eye-slash` by number sequence);
8 are the 96-grid drawings above (`spool` exists as a file but was never in that sprite);
and 3 grid-24 symbols (`fan`, `humidity`, `theme`) match no Heroicons release and are
Jeremy's drawings that are not in the working files at all. Those three are vent-specific
and are not imported here.

## The marks: `art/`, generated by `tools/art/gen_marks.py`

The family mark: Jeremy's panda face over this product's light bar. The face is the same
primitives his PandaVentOS banner draws; the bar is this project's. The vent carries the
face alone, the Status carries the face over its bar, so two tabs on one network are one
project line and two products (D-030). The favicon was designed at 16 px first; four options
were rendered at 16, 64 and 180 on both grounds and looked at before this one was chosen.

`art/MARKS.md` lists every output with its size and sha256; `gen_marks.py --check` proves
the committed files are what the generator produces.
